---
name: schemify-plugin
description: Start a Schemify plugin from a language template and build it to a working module. Use when the user wants to write, create or scaffold a Schemify plugin, in any language.
---

A plugin starts as a copy of a **template** in `examples/plugins_new/<lang>/`. Each template is a complete plugin repository root: a short plugin written on Schemify's library for that language, the language's own build files (Cargo, Makefile, CMake, `build.zig`, `go.mod`, npm, dub, nimble, SwiftPM), a `schemify.project`, and a `hello.wasm` that `cargo test -p schemify-plugin --test templates` proves loads. The libraries live in `crates/protocol/abi/sdk/<lang>/` (Rust uses the `schemify-abi` crate). Each language's build command and gotchas are in `docs/plugins/languages.md`: read that language's section before step 2.

## Steps

1. **Choose.** Ask the user, with `AskUserQuestion`, which language: the options are the directory names under `examples/plugins_new/`. Also ask what the plugin should do, its name (a bare word such as `net-stats`) and where its repository goes (default: a sibling of this checkout), unless the request already says. If the language has no template, show the "cannot load" table in `languages.md` and offer the nearest template. Done when language, name, behaviour and destination are known.
2. **Copy and repoint.** Copy the template directory to the destination, leaving out build outputs (`target/`, `build/`, `zig-out/`, `.zig-cache/`, `node_modules/`) and `hello.wasm`. The template finds the library by a path relative to this checkout. Repoint it the way the comment beside that path says: a git dependency pinned to this checkout's commit (`git rev-parse HEAD`), or a vendored copy of `crates/protocol/abi/sdk/<lang>/`. Done when the build files name no `../../../` path.
3. **Rename.** Replace every `hello` with the plugin's name: the source, the command (`hello.count` becomes `<name>.<verb>`), the UI node (`tools.hello`), the manifest (`plugin <name> path <module>.wasm`) and the build output name. Done when `grep -rn hello <dest>` prints nothing.
4. **Implement.** Write the behaviour through the library: events, host reads and output records. Look up what the plugin needs in `docs/spec/plugin-abi.md`: tables and column ids in §4 (the library names them), events in §6, output records in §7, and capabilities in §5. Add each capability as a `grant` line in `schemify.project`. Done when every command and contribution the user asked for is in the source.
5. **Build and check.** Build with the language's build system (the command is in `languages.md`), then from this checkout run `cargo run -p schemify-plugin --example check -- <dest>/<module>.wasm <command>…`. Done when `check` exits 0 and prints the contributions and logs the user asked for. A load failure names its cause: an import outside `schemify` means a runtime or libc slipped in, so apply the language's notes in `languages.md`.
6. **Hand off.** `git init` the destination, commit the source together with the built module, and point the user to `docs/plugins/testing.md` (a guest test plus CI) and `docs/plugins/publishing.md` (install from the repository URL). Done when the user has the path, the module size and the commands to try.
