# Testing (binding, D37)

Methodology: `../../Zig/TESTING-METHODOLOGY.md` (oracles before coverage; several independent oracles per area; assertions are the fuzzer's oracle; deterministic seed-replayable randomized tests; coverage as a gap-finder; mutation testing; tiers; exit criteria). Rust tools: `proptest`, `cargo-fuzz` + `arbitrary`, `cargo-mutants`, `cargo-llvm-cov` (ratchet only).

**Every feature lands with its oracle in the same change.** Every user or LLM bug report becomes a new oracle or generator feature, not just an example test.

## Oracles per area

The plugin rows (`import`, `interop`, `gmid-lut`, and the cktimg and PDK manager tests) are binding on the plugins' own repositories, whose CI runs them against a pinned Schemify revision and nightly against `main` ([../plugins/testing.md](../plugins/testing.md)); this repository's CI runs only the core.

| Area | Oracle(s) |
|---|---|
| `format` | Property: `parse(write(doc)) == doc`; `write` canonical and idempotent (`write(parse(s)) == s` for canonical `s`); any reorder of rank-3 records parses to the same model. Fuzz the reader: no panic, errors only from the declared set. `merge3`: non-conflicting edits commute (`merge(O, A, B) == merge(O, B, A)`), `merge(O, A, O) == A`, model-based PBT over random edit scripts; verbatim diff3: line edits separated by a line both sides keep merge to both edits applied, symmetrically; a clean result that breaks the kind rules conflicts. |
| `expr` | Differential vs a naive tree-walking reference evaluator written only for tests; differential vs ngspice for the SPICE-compatible subset; properties: canonical number text round-trips (`num(str(x)) == x`); dependency-graph recompute == full recompute after random edits; one-pass cycle report vs naive reachability (cycles real, covering exactly the self-reaching nodes; acyclic order == `topo_order`). Fuzz parser. |
| `doc` | Stateful model-based PBT: random edit sequences vs a naive model; undo-all == original; journal replay after a simulated crash at every op == pre-crash state (seeded, DST-style); load(save(x)) == x; the ops `Project::applied` reports, committed to a mirror, reproduce every request's result. |

Metamorphic: hierarchical vs flattened → same sim results; renaming an unlabeled net never changes emitted labeled nets. Determinism: byte-identical across platforms and runs. **Verilog** (no xschem golden): Icarus Verilog parses and elaborates every fixture netlist of the dialect (`netlist/tests/iverilog.rs`, CI installs `iverilog` on Linux; a missing module or port fails it). **Spectre**: snapshots only, no second oracle: no Spectre-syntax simulator runs in CI (Spectre is proprietary; ngspice and Xyce read SPICE syntax). | `interop` Virtuoso bridge and xschem export (`examples/plugins/interop`) | No Virtuoso in CI, so: the shipped SKILL is in a prefix subset a test-only interpreter executes exactly, against a mock Virtuoso whose every function checks the documented signature (`tests/skill/`, `skill_lint` fails on unknown calls or arities). SKILL side (`virtuoso_skill`): escaper = `sfyx::write_str` and `lineread` gives strings back (property); dumps canonical and equal to goldens; goldens load and dump back identically; callbacks in CDF order, failures logged; malformed input saves nothing. ## Tiers

As implemented in `.github/workflows/` (Rust pinned to the workspace MSRV 1.95.0, the rustc
`flake.lock` pins; bump both together). "Not yet" marks the gaps of the binding plan.

| Tier | Where | Runs |
|---|---|---|
| pre-commit | local | `cargo test -p <touched crates>`, `cargo clippy -p <crate> -- -D warnings`, `cargo fmt` |
| merge | `ci.yml`, every push to `main`/`ci/*` and every PR | **test** (ubuntu, macos, windows): `fmt --check`, `clippy --workspace --all-targets -D warnings`, `cargo test --workspace --no-fail-fast`, which also replays the checked-in fuzz corpora (`<crate>/fuzz/corpus/<target>/`, minimized by the manual `fuzz-corpus` job) through the fuzz targets' own oracles (`<crate>/tests/fuzz_corpus.rs`, `fuzz/oracles/`). **wasm**: clippy of the web `cfg` paths, release build of every web crate incl. `schemify-app` for `wasm32-unknown-unknown`, `wasm-bindgen` bundle (artifact `web`, D39 ≤ 8 MiB gzip), headless-Chrome smoke test (`tests/web/smoke.sh`), the CLI for `wasm32-wasip1`. **determinism** (D32): `tests/determinism/run.sh` on each OS and under wasmtime (`netlist` of every app/elab/netlist fixture in all five dialects with exit codes, `fmt` rewrites), byte-compared across the four. **guests** (Nix): `ui/build.sh` (the default UI and the host test guests; size limits; byte-reproducible: pinned toolchain, host paths remapped), host tests against the rebuilt guests, `run` tests with the real simulators, then every committed `.wasm` must equal its rebuild (artifact `guests`). **flake**: `nix flake check`, `nix build .#schemify`. |
| nightly | `nightly.yml` (03:17 UTC), `mutants.yml` (weekly, Sunday) | **fuzz**: every `crates/*/fuzz` target (`format/parse`, `format/merge3`, `expr/compile`, `cli/rpc_decode`) for 60 min from the checked-in corpus, corpus kept in the actions cache and uploaded with crash inputs; the manual `fuzz-corpus` job (`-f only=fuzz-corpus`) minimizes corpora from this repository's own seeds for check-in. **perf**: every `--ignored --release` perf test (their D39 budget asserts) in 5 rounds and `tests/perf/gate.sh`: a metric's median over the rounds (each round a test's best of its repetitions) > 10% slower than `tests/perf/baseline.txt` (measured on GitHub `ubuntu-latest`) fails. **coverage**: `cargo llvm-cov --workspace`; `tests/coverage/ratchet.sh` fails when line coverage drops more than 0.5 points below `tests/coverage/floor.txt` (raised, never lowered). **mutants**: `cargo mutants` on `format expr doc elab netlist` (≤ 5 shards at once), survivors uploaded (report only). `-f only=<job>` runs one nightly job on demand. |
| release | `release.yml`, tag `v*` | `schemify` and `schemify-gui` for Linux x86_64 (built in `manylinux_2_28`, checked to need glibc ≤ 2.28), macOS aarch64 and x86_64 (cross-built on Apple silicon), Windows x86_64 (stripped, LTO) and the web bundle, attached to a draft release whose notes are the checklist below (`.github/release-notes.md`). A push to `ci/release*` is a dry run. |

## Release exit criteria

Fuzzers ≥ 24 CPU-h per target with no new crash and a plateaued corpus; byte-identical outputs on all four platforms; coverage not below the last release; D39 budgets met; known-gaps list written.

## Code rules that feed the oracles

TigerStyle asserts (≥ 2 per function on average, positive and negative space); bounded loops and queues; every table has a capacity.
